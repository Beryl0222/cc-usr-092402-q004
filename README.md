# 碎片文化消费节律保护

本项目在既有"预算与消费事件"领域资料之上，演进为一套**可携带时长账本**（portable time ledger）的参考实现：电视暂停后手机续播、家庭成员借用车机、离线晚到、跨时区旅行等跨设备场景下，任何一段内容只扣减一次，账单行可逐级展开到原始片段，同批上报重放多次结果逐字节一致。

资料只包含领域约定与纯函数参考实现，全部数据为虚构，不包含真实个人信息、生产连接或外部账号。

## 目录

- `src/events.js`：事件目录（终端上报层 / 规则层 / 账本层）与最小字段校验。旧入口 `src/culture_time_budget.js` 保持兼容。
- `src/time.js`：设备时钟漂移修正、跨时区切片、当地日期与周期键。
- `src/rules.js`：带版本有效期的成员关系、设备绑定、内容包规则，任意时刻取当时有效版本。
- `src/ledger.js`：时长账本核心引擎（幂等摄取、位置去重、封账快照、追加式调整、申诉裁定、证据授权、账单行追溯）。
- `data/sample.json` / `data/scenario.json`：用于核对格式的虚构事件与跨设备场景。
- `tests/`：17 个契约/场景测试，覆盖客服申诉中出现的各类情况。

## 本地核对

```bash
npm test   # 17 个场景全部通过

```

## 快速试算

```js
import { TimeLedger } from "./src/ledger.js";
const ledger = new TimeLedger(events, { periodType: "DAY" });
ledger.explainLine("acct-004", "2026-09-20"); // 客服视角：冻结账单 + 调整版本 + 原始片段
```

## 模型总览

事件只追加、不修改；`received_at` 表示平台收到时刻（缺失时取 `occurred_at`）。引擎是输入事件列表的纯函数，因此可随时对整个事件库做确定性重放。详细设计见 [`docs/ledger.md`](docs/ledger.md)。

1. **终端上报层**：`PLAYBACK_SEGMENT`（半开区间 `[start,end)` 与内容位置 `[pos_start,pos_end)`）、`SESSION_SYNC`（对表 + 声明时区）、`OFFLINE_DOWNLOAD`（离线计秒授权窗）。
2. **规则层**：`RELATIONSHIP_RULE`、`DEVICE_BINDING`、`CONTENT_PACK_RULE` 均带 `version` 与 `[valid_from, valid_to)`；新版本自动收口旧版本。
3. **账本层**：`PERIOD_CLOSED`（封账，仅冻结当时已收到数据形成的数字快照）、`LEDGER_ADJUSTMENT`（人工追加调整）、`DISPUTE_RULING`（逐片段裁定）、`EVIDENCE_GRANT`（最小范围查验授权）。

## 针对本次申诉的逐条回应

| 申诉情况 | 处理方式 |
| --- | --- |
| 电视暂停、手机续播被算两段 | 同 `(观看人, 内容, 续播链路)` 内对"时间轴 ∪ 内容位置轴"交叠首写者胜出；位置不重叠的续播各计，重叠回看只扣一次（`tests/ledger.test.js` 场景 3） |
| 弱网/换设备重复上报 | 时间×位置盒相同，增量恒为 0；事件 ID 重复直接幂等丢弃；整库重放结果一致（场景 4、17） |
| 家庭成员借车机，时长记到主人名下 | 按片段每个时刻当时有效的 `RELATIONSHIP_RULE.attribution` 归属；无关系借用人不静默计入主人（场景 6） |
| 周期中途成员关系变化 | 片段在规则版本边界切开，变更前计主人、变更后计成员，各 60 分钟（场景 7） |
| 设备时钟不准 | 同步点间分段线性对表（吸收漂移率），按平台参考时刻归属与归日（场景 8） |
| 跨时区旅行 | 以不晚于参考时刻最后一次同步声明的 IANA 时区切片，按当地日切分；DST 边界午夜正确（场景 9） |
| 离线数据晚到，周期未封账 | 直接重算修正开放周期（场景 10） |
| 离线数据晚到，周期已开票/退款 | 原账单冻结，按原子身份集合差集追加 `LATE_REPORT`/`CORRECTION`/`DISPUTE_REFUND` 调整，绝不重写（场景 11、13） |
| 撤销家庭共享 | 新版本 `attribution=NONE` 在撤销刻收口旧版本；新片段立即标记 `REVOKED` 停算，旧账单保留（场景 12） |
| 撤销后查验旧证据 | 非本人须持覆盖单个账单行、未过期的 `EVIDENCE_GRANT`；越权/过期/他人周期一律拒绝（场景 12） |
| 平台间差异逐片段申诉 | `DISPUTE_RULING` 精确指向 `segment_ref`；开放周期直接冲销重算，封账周期只生成负向调整（场景 13） |
| 客服从账单行追查 | `explainLine` 返回冻结账单、全部调整版本、每个原子的原始上报/对表点/规则依据/去重原因（场景 14） |

## 账单版本公式

对任一账单行（账号 × 周期）：

```
当前有效金额 = 封账快照（PERIOD_CLOSED 时刻已收到事实物化结果，永不改变）
             + 调整版本序列（晚到事实差集 + DISPUTE_REFUND + 人工 LEDGER_ADJUSTMENT）
             ；未封账周期则为全量实时物化结果
```

快照只引用原子 ID 与金额；调整与原账单通过确定性 ID（FNV-1a 派生）关联。重复投递、重复封账、重复裁定、重复人工调整均幂等。

## 边界与定位

这是领域模型与纯函数参考实现，刻意不包含持久化、服务接口与并发控制。生产落地时需要补：事件存储的 only-append 约束、`received_at` 可信时间戳、封账调度、原子 ID 的稳定哈希策略（当前用 FNV-1a，可替换为内容寻址），以及对 `drift_ppm_tolerance` 超差片段的拒入/告警策略。
